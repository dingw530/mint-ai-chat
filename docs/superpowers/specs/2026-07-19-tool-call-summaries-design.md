# 工具调用摘要展示设计

## 目标

在工具调用过程中向用户展示简短、易懂的状态摘要，让用户知道工具正在做什么以及执行结果的大致情况。本期先覆盖 Wiki 相关工具，同时把能力抽象到所有工具都可以复用。

## 范围

本期覆盖：

- `wiki_search`
- 其他现有 Wiki 工具的调用开始摘要和结果摘要
- ReAct 工具事件协议、服务端工具抽象、聊天界面展示

本期不改变：

- 模型的工具选择和请求格式
- 工具返回给模型的数据结构
- 完整工具参数和结果的查看能力
- 非 Wiki 工具的定制文案；它们使用通用回退文案

## 设计方案

### 工具摘要抽象

在 `BaseTool` 中增加可选的摘要能力：

```ts
getCallSummary?(input: Input): string;
getResultSummary?(result: Output): string;
```

工具执行器在工具执行前调用 `getCallSummary`，执行成功后调用 `getResultSummary`。未实现摘要方法的工具继续使用通用文案，不要求一次性修改所有工具。

摘要方法只负责界面文案，不改变工具结果，不参与模型上下文，也不承担日志职责。

### Wiki 工具文案

`wiki_search` 根据输入模式生成摘要：

- question 模式开始：`正在查找：{question}`
- paths 模式开始：`正在读取 {count} 个 Wiki 文件`
- question 模式成功：`找到 {total} 个相关页面，返回前 {returned} 个`
- paths 模式成功：`已读取 {count} 个文件`

其他 Wiki 工具使用同样的输入/结果摘要约定，文案只保留动作、数量、状态或短文件名，不展示正文。

### 事件协议

为 `tool_call_start` 和 `tool_call_end` 增加可选字段：

```ts
summary?: string;
```

开始事件携带调用进行中的摘要，结束事件携带执行结果摘要。字段保持可选，以兼容未提供摘要的工具和旧事件。

工具执行失败时沿用现有错误事件及错误信息；失败摘要不覆盖真实错误原因。

### 前端状态与展示

前端 ReAct 工具步骤新增可选 `summary` 字段，并分别保存开始和结束阶段的摘要。

工具行展示规则：

- 执行中：`工具名 · 摘要`，保留动态状态指示器
- 成功：`工具名 · 摘要`，同时显示耗时
- 失败：优先展示错误信息，摘要作为辅助信息或不展示
- 摘要最大约 80 个字符，超出后截断
- 完整参数和完整结果仍放在可展开区域
- 没有摘要时回退到现有的“调用工具/工具返回”文案

## 数据流

```text
模型产生 tool call
  -> ReAct 循环解析参数
  -> 工具摘要接口生成开始摘要
  -> tool_call_start(summary)
  -> 执行工具
  -> 工具摘要接口生成结果摘要
  -> tool_call_end(summary)
  -> 前端 reducer 保存摘要
  -> 工具调用行展示摘要
```

摘要生成失败不应阻断工具执行；服务端应回退到无摘要流程。

## 测试策略

服务端测试：

- `wiki_search` question 模式生成正确的开始和结果摘要
- `wiki_search` paths 模式生成正确的开始和结果摘要
- 未实现摘要方法的工具能够正常执行并发送无摘要事件
- 摘要生成异常不会阻断工具执行
- 工具事件包含可选摘要且保持原有字段和生命周期行为

前端测试：

- reducer 能保存开始和结束摘要
- 摘要能在工具调用行中展示
- 超长摘要会被截断
- 工具失败时仍展示错误信息
- 没有摘要时使用回退文案

验证命令包括相关 Vitest 测试、服务端 TypeScript 检查、客户端构建和全量测试。

## 验收标准

- 用户能在 Wiki 工具执行期间看到简短的进行中描述。
- 工具结束后用户能看到结果数量或读取数量等摘要。
- 摘要不会暴露完整参数、完整 Wiki 内容或过长文本。
- 新增其他工具摘要时只需在工具自身实现摘要方法，不需要修改事件协议和前端业务判断。
- 没有摘要的工具、旧事件和失败流程保持兼容。
