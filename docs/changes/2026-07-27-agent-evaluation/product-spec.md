# Agent 评估基础设施

## 背景与目标

当前 Mint 已有 ReAct 单元测试和运行事件，但缺少可重复的 Agent 任务评估。目标是建立第一版离线评估能力，用固定数据集运行 Agent，验证最终结果和工具轨迹，并输出可用于回归比较的 JSON 报告。

## 范围

- 做：评估用例模型、内置小型数据集、轨迹收集、确定性验证器、统计报告和 CLI。
- 做：支持注入 Agent executor，便于单元测试和未来接入真实模型。
- 不做：数据库持久化、Web UI、LLM-as-a-Judge、多模型排名和生产流量采样。

## 业务规则

1. 安全违规和明确的任务失败不能被其他维度的分数抵消。
2. 工具调用必须按轨迹逐项验证，最终答案不能替代最终状态验证。
3. 同一数据集可重复运行，报告必须包含每个用例的独立结果。
4. 评估器不能调用真实外部工具作为默认测试路径。

## 验收标准

- AC-1：可以加载 JSON 数据集并校验用例结构。
- AC-2：可以运行注入的 Agent executor，收集最终答案、工具调用、轮数、重试、循环和耗时。
- AC-3：可以验证必须/禁止工具、工具调用上限、答案关键词和安全审批条件。
- AC-4：报告包含 Pass@1、Pass^k 所需的逐次结果、工具成功率、平均轮数、平均调用数、重试率、循环率和平均延迟。
- AC-5：CLI 可以运行内置数据集并将报告输出为 JSON。
- AC-6：单元测试覆盖正常、失败、结构非法和安全否决场景。
- AC-7：`security-001` 必须针对 `write_file` 触发审批，审批前不得执行该工具，审批事件本身可作为任务完成信号。
- AC-8：`agent-eval/viewer` 静态页面可以直接读取同目录 `report.json`，展示汇总指标和逐次用例诊断，不依赖 Mint 服务端。

真实模型评估通过 CLI 参数 `--live` 显式开启，例如 `npm run eval:agent -- run --dataset smoke --runs 3 --live`；评估 CLI 会优先读取 `server/.env`，再读取根目录 `.env`，默认 CLI 只验证评估框架，不产生模型请求。
