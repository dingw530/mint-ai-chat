# 上下文工程能力改造

## 背景与目标

当前 ReAct 上下文主要依赖固定消息数量的滑动窗口，无法按 token 预算保护模型调用，也没有对历史轨迹进行压缩。长工具调用、文件读取和多轮任务会导致上下文膨胀或丢失关键决策。

目标是在不改变现有 SSE、数据库和公开 API 契约的前提下，完成：

1. 基于 token 预算的上下文管理；
2. 替代简单滑动窗口的结构化历史保留策略；
3. 接近预算阈值时的上下文压缩机制。

## 范围

### 做

- 在 ReAct 每轮模型调用前估算上下文 token，并预留输出空间。
- 按完整上下文单元保留最近任务，避免拆开 user/assistant/tool 闭环。
- 对较早轨迹生成结构化摘要，保留决策、验证结果、失败路径、TODO、文件名和 URL 等关键事实。
- 压缩失败时提供确定性的降级结果，并继续执行安全的预算裁剪。
- 增加上下文边界、压缩和异常场景测试。

### 不做

- 不修改数据库 schema，不持久化完整 tool 消息。
- 不改动公开设置 API，不新增用户可配置项。
- 不在本变更中实现记忆检索、Prompt Cache、提示注入防护或工具结果 artifact 存储。
- 不改变现有 SSE 事件格式和工具执行语义。

## 业务规则

- 上下文预算使用内部默认值，并为模型输出预留空间。
- 当上下文超过预算的 80% 时触发压缩，目标降至预算的 60% 左右。
- system 消息始终保留且不参与历史压缩。
- 压缩以 user 开始的完整上下文单元为边界；当前最新单元优先保留。
- 压缩摘要必须保留可操作标识符：文件名、路径、URL、UUID、hash、验证状态和未完成事项。
- LLM 摘要失败时不能阻断对话；使用确定性摘要，并继续裁剪低优先级的旧内容。

## 验收标准

- AC-001：上下文调用前不超过内部 token 预算，并预留输出空间。
- AC-002：裁剪不会留下脱离 assistant tool call 的 tool 消息，也不会破坏最新任务单元。
- AC-003：上下文达到 80% 阈值时触发压缩，压缩结果包含结构化摘要标记。
- AC-004：摘要失败时请求仍可继续，且最终上下文不超过预算。
- AC-005：现有 ReAct 循环、并行工具调用、SSE 事件和原有测试不回归。

## 风险与依赖

- token 估算不是模型 tokenizer 的精确结果，因此保留安全余量。
- 摘要可能产生有损信息，必须保留关键标识符和验证状态。
- 额外摘要调用会增加延迟和成本；仅在达到阈值时触发。
