# Wiki 引用归一化

## 背景与目标

真实 Wiki/RAG 评测表明，检索可命中目标资料，但模型会以 `[R1]`、`[citation:1]` 或 `[1]` 等变体输出已知来源，导致 Mint 无法生成可追溯的来源卡片。目标是在不接受伪造引用的前提下，将本轮已检索来源的常见标记归一化为 Mint 的显示引用。

## 用户与场景

- 作为提问者，我希望 Wiki 回答中的来源稳定显示为可打开的来源卡片，而不是裸编号、无效链接或没有引用。
- 作为维护者，我希望评测可区分“未检索到来源”和“检索到但格式变体未落地”。

## 范围

- 做：将 `[C1]`、`[1]`、`[R1]`、`[citation:1]` 映射到本轮实际存在的 `C1`。
- 做：让生产 A2UI 与 `agent-eval` 使用等价的安全识别规则，并覆盖跨 SSE chunk 的标记。
- 做：在评测 CLI 输出不含敏感内容的逐用例进度，并允许静默模式。
- 做：保留未知、残缺或不能映射的标记为非引用，禁止由路径文本或任意编号生成来源卡片。
- 不做：自动将所有检索结果追加到答案末尾；不把普通 Markdown 路径视为可信引用；不改变 Wiki 检索、数据表或公开 API。

## 业务规则

1. 只有本轮 `wiki_search` 产生的引用 ID 可以生成来源卡片或评测引用。
2. 变体中的数字 `n` 仅映射至已知 `Cn`；不存在时不得生成卡片。
3. 有效变体在回答正文中统一显示为 `[C#]`，卡片继续按首次出现重编号。
4. 有序列表（如行首 `[1] 先检索`）不得误判为引用。

## 验收标准

- AC-1：生产回答中的 `[R1]`、`[citation:1]`、`[1]` 可落地为已知来源卡片，并统一显示为 `[C1]`。
- AC-2：分片到达的变体标记仍能正确落地；未知引用与有序列表不会生成卡片。
- AC-3：评测提取与生产规则一致，可从这些有效变体映射回本轮检索来源。
- AC-4：现有规范 `[C#]`、展示顺序与来源卡片行为保持不变。
- AC-5：评测运行输出 start/judge/done 进度、当前/总数、用例 ID、轮次、状态和耗时；`--quiet` 可关闭。

## 风险与依赖

- 不同模型仍可能输出更复杂的畸形 Markdown；本次只支持已在真实报告中出现且可无歧义映射的变体。
- 原始 DSML 工具调用文本泄漏属于适配器问题，不由本变更掩盖。
