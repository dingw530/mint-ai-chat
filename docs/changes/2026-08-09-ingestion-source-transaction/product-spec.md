## 背景与目标

上传入口在后台摄入开始前就把原始文件写入 `sources/`。当解析、AI 编译、证据校验或后续索引流程失败时，失败输入仍会被当作正式 Source 留在知识库中。

目标是让正式 `sources/` 只包含成功提交的摄入输入；失败任务不得新增正式 Source。

## 范围

### 本次做

- 上传和 Chat 文件先写入 Wiki 目录下的 `ingestion-pending/` 暂存目录。
- 编译及后续注册、索引、manifest 流程成功后，将本次暂存文件移动到 `sources/`。
- 编译失败、后续提交失败、解析失败和取消路径清理暂存文件。
- 多文件摄入按文件独立处理，成功文件保留，失败文件不进入 `sources/`。
- 兼容已存在的 `sources/...` 任务 payload，不删除历史正式文件。

### 本次不做

- 不新增数据库 schema。
- 不清理历史已经落入 `sources/` 的失败文件。
- 不实现跨进程崩溃恢复的全量暂存目录扫描；重启后的任务仍可读取其持久化暂存路径。

## 验收标准

- **AC-001**：AI 编译或证据校验失败后，`sources/` 不新增本次输入文件。
- **AC-002**：摄入完整成功后，本次 Source 出现在 `sources/`，任务结果返回正式路径。
- **AC-003**：后续注册或搜索索引失败时，本次已经提交的 Source 被回滚，不遗留在 `sources/`。
- **AC-004**：Chat 多文件一成功一失败时，只保留成功文件的正式 Source；失败文件不进入 `sources/`。
- **AC-005**：已有正式 `sources/...` 的旧任务失败时，不误删该历史文件。

## 风险

- 进程在文件移动和后续数据库写入之间异常退出时，页面、数据库和 Source 仍可能需要后续一致性修复；本次先覆盖正常异常路径。
- 暂存目录可能保留极端进程崩溃产生的孤儿文件，后续可增加 TTL 清理任务。
