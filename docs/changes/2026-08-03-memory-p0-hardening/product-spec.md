## 背景与目标

Mint 已具备结构化记忆、异步提取、版本替代和 SQLite 持久化，但当前 P0 风险集中在五个方面：记忆正文可能进入普通日志；LLM 操作缺少运行时 Schema 防线；多步记忆更新缺少批量事务；提取任务会扁平化对话轨迹并重复处理；缺少不含敏感正文的审计记录。

本变更目标是让记忆链路在生产运行中满足“不会误写、不会泄露、失败可回滚、重复可安全重试、来源可追溯”。

## 用户与场景

- 用户发送包含个人资料或项目背景的消息，记忆提取失败或重试时不影响主聊天，也不产生重复 active 记忆。
- 用户修改已有事实时，新旧版本保持一致，旧版本可追溯。
- 开发者或审计人员需要定位一条记忆的来源、操作类型和失败原因，但不能通过普通日志看到完整敏感正文。

## 范围

### 本次要做

- 增加记忆相关日志脱敏和安全错误日志约束。
- 对结构化记忆操作执行运行时类型、枚举、长度和数值范围校验。
- 将同一批 ADD/UPDATE/NOOP/DELETE 与审计记录放入 SQLite transaction。
- 保留消息角色、顺序、ID 和时间信息供提取使用；任务按消息快照幂等处理。
- 增加不保存完整敏感正文的 `memory_events` 审计记录。

### 本次不做

- 不引入向量数据库、Embedding、Reranker 或新的语义检索方案。
- 不实现主动服务规则、知识图谱或程序记忆。
- 不改造记忆管理面板的交互和现有 CRUD 契约。
- 不改变主聊天 SSE 链路和已有 `memories` 字段兼容性。

## 业务规则

- BR-201：普通日志不得输出完整记忆内容、用户 prompt、assistant 原文或结构化 `value`。
- BR-202：非法或不完整的记忆操作必须整批拒绝，不得部分写入。
- BR-203：单批记忆操作与版本替代、删除标记和审计事件必须原子提交。
- BR-204：同一 conversation 的同一消息快照重复处理不得产生重复有效记忆或重复有效版本。
- BR-205：提取输入必须保持 user/assistant 角色、消息顺序、消息 ID 和创建时间。
- BR-206：审计事件只保存操作摘要、来源 ID、候选 ID、结果 ID、状态和错误原因，不复制完整敏感正文。
- BR-207：已有记忆 CRUD、memoryEnabled 开关和 SSE 主流程保持兼容。

## 验收标准

- AC-201：调用记忆上下文构建、提取失败和任务失败路径后，普通日志中不出现记忆正文、用户 prompt 或 assistant 正文。
- AC-202：包含未知 action、空 key、超长 content、非法 score 或错误 value 类型的 LLM 返回被拒绝，数据库和审计状态不产生有效写入。
- AC-203：合法 ADD/UPDATE/NOOP/DELETE 操作按 Schema 通过，`confidence` 和 `importance` 被限制在 0～1。
- AC-204：批量操作任一步写入失败时，active、superseded、deleted 和审计记录全部回滚。
- AC-205：UPDATE 后同一单值 `memory_key + subject` 只有一个 active 版本，旧版本为 superseded 并保留来源。
- AC-206：提取器收到的输入保留原始消息角色、顺序、message ID 和 createdAt，不再将全部 user/assistant 内容分别拼接。
- AC-207：同一 conversation/message 快照重复入队、重复 claim 或失败重试，不产生重复 active 记忆；新消息到达时不会被旧快照吞掉。
- AC-208：每次成功或失败的记忆操作都有可查询的 `memory_events` 摘要，且摘要不含完整敏感正文。
- AC-209：既有 memoryService、messageService、memory job、CRUD 回归测试和构建通过。

## 非功能性需求

- NF-P0-001：记忆处理仍为异步路径，不阻塞 SSE 首字节和主聊天完成。
- NF-P0-002：记忆写入只使用现有 SQLite 和 migration 机制，不直接修改用户数据库 schema。
- NF-P0-003：失败任务继续遵守有限次数退避和服务重启恢复。
- NF-P0-004：审计与错误日志可用于定位问题，但不得成为敏感正文的第二份存储。

## 风险与依赖

- 变更涉及 `sendMessage`、记忆提取和 worker，影响范围为 HIGH；必须先有基线测试并保持接口兼容。
- 现有工作区存在用户未提交改动，实施时只修改本变更允许范围内的记忆相关文件和测试。
- 本变更为后端/数据链路变更，不新增浏览器验收场景；Harness 中明确记录 browser-ac 不适用。
