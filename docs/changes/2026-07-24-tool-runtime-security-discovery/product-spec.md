# 工具运行时安全与 MCP 主动发现

## 1. 背景与目标

当前 Mint 的内置工具经过 `ToolExecutor`，而 MCP 工具在独立路径中直接调用；同时，已连接 MCP Server 的工具会被全量注入 Agent 上下文。Bash、HTTP 和 MCP 也缺少统一的风险、权限和审批边界。

本变更将工具系统推进到可治理的统一运行时：

1. 所有工具调用经过统一的解析、Schema 校验、权限判定、超时/取消、重试、结果序列化和审计路径。
2. Bash、HTTP、MCP 具备可配置的安全策略边界，默认拒绝明显越界行为，并为高风险操作保留审批入口。
3. MCP 工具不再默认全量注入；Agent 先看到轻量目录，需要时通过工具发现能力加载具体工具 Schema。
4. 保持现有内置工具、MCP 配置和普通对话调用的兼容性。

## 2. 用户与场景

### US-001：统一工具执行

作为 Agent 运行时维护者，我希望内置工具和 MCP 工具共享同一执行管线，以便安全策略、错误处理和审计行为一致。

### US-002：受控执行高风险工具

作为用户，我希望 Bash、HTTP 写操作和 MCP 工具受权限与风险策略保护，以避免 Agent 在未授权范围内修改主机、访问内网或调用外部副作用接口。

### US-003：按需发现 MCP 工具

作为 Agent，我希望先搜索工具目录，再按需加载工具定义，以降低上下文占用并提升大量 MCP 工具下的选择准确率。

## 3. 范围

### 3.1 本期做

- 新增统一 Tool Runtime/执行上下文，MCP 调用接入该运行时。
- 统一输入校验、权限策略、超时、取消、重试、结果序列化和调用审计。
- 为工具增加风险级别、来源和副作用元数据。
- Bash 增加工作目录/命令策略边界，并支持高风险操作的审批判定接口。
- HTTP 增加 URL 访问策略、内网地址拦截和写方法风险判定。
- MCP 增加 Server/工具目录检索和按需加载机制。
- 保留兼容模式，确保未启用主动发现时既有 MCP 配置仍可工作。
- 为正常、拒绝、超时、取消、动态发现和统一执行路径补充测试。

### 3.2 本期不做

- 不实现完整外部事件通道、定时器和多渠道用户沟通。
- 不实现 OS sandbox、容器或 microVM；本期只建立策略接口和默认防护边界。
- 不改造 MCP 协议本身，不引入新的外部消息队列。
- 原设计不实现完整的人类审批 UI；本次补充将最小批准/拒绝消费 UI 纳入范围，仍不实现多渠道审批编排。

### 3.3 本次补充：审批消费闭环

- 将 `approval_required` 从 Runtime 结构化传递到 ReAct SSE 和聊天 UI。
- 用户可在工具调用卡片中批准或拒绝一次审批请求。
- 批准请求只允许绑定会话、一次性消费，并在 Runtime 中以显式批准上下文执行原始调用。
- 本次不持久化审批请求；服务进程重启后未消费请求失效。

## 4. 业务规则

- BR-001：任何工具调用必须先完成工具解析和输入 Schema 校验，校验失败不得执行。
- BR-002：任何工具调用必须经过统一权限策略；策略默认拒绝未知工具和未知来源。
- BR-003：只读工具可配置为低风险；Bash、HTTP 非 GET、MCP 未知副作用工具默认不得自动放行。
- BR-004：工具超时必须返回结构化超时错误；可取消工具必须接收并响应 `AbortSignal`。
- BR-005：MCP 工具的真实执行必须经过统一 Runtime，不得从 MCP 服务直接绕过执行器。
- BR-006：默认 Agent 不接收 MCP 工具完整 Schema，只接收服务器/工具轻量目录与发现工具。
- BR-007：发现结果必须包含来源 Server、工具名、描述和 Schema；未发现时返回明确的未找到结果。
- BR-008：工具返回值统一进入结果序列化策略；大结果不得静默截断。
- BR-009：敏感凭证不得进入工具描述、审计日志或错误消息。
- BR-010：旧配置未开启动态发现时，系统提供显式兼容开关，不改变已有工具名格式。

## 5. 验收标准

### 统一 Runtime

- AC-001：内置工具和 MCP 工具均经过同一个公开 Runtime 入口；测试可证明 MCP 不再直接调用底层 `callTool`。
- AC-002：无效 JSON、Schema 校验失败、权限拒绝均不会触发实际工具执行。
- AC-003：工具超时、取消、重试和结果序列化对内置工具与 MCP 工具表现一致。
- AC-004：每次调用产生结构化审计记录，至少包含工具来源、工具名、会话、风险级别、结果状态和耗时；不得记录密钥。

### 安全边界

- AC-005：Bash 能拒绝配置禁止命令、工作目录外路径和高风险命令；策略结果包含拒绝原因。
- AC-006：HTTP 能拒绝 loopback、私有网段和非允许协议 URL；GET 与写方法风险等级不同。
- AC-007：MCP 工具能按 Server 策略限制，并对未知副作用工具返回需审批状态。
- AC-008：高风险调用在无审批结果时不得执行；低风险只读调用可自动执行。

### MCP 主动发现

- AC-009：默认工具列表不包含所有 MCP 工具完整 Schema，只包含发现所需的轻量目录信息。
- AC-010：Agent 可通过发现工具按关键词/能力描述检索候选工具，并加载指定工具 Schema。
- AC-011：加载后的工具可在当前会话继续调用，工具名仍保持 `serverName__toolName` 兼容格式。
- AC-012：发现无结果、Server 不可用、加载失败都有结构化错误，不影响内置工具调用。

### 兼容与验证

- AC-013：既有内置工具测试和 MCP 配置解析测试继续通过。
- AC-014：新增安全策略、统一执行、动态发现测试通过，TypeScript 构建通过。
- AC-015：高风险工具未获批准时，ReAct 流输出结构化 `approval_required` 事件，包含审批 ID、工具名和原因，且工具不执行。
- AC-016：聊天 UI 消费 `approval_required` 事件并展示批准/拒绝操作；用户可见状态不会误标记为成功。
- AC-017：批准接口校验会话归属和一次性 token；批准后原始工具调用经 Runtime 执行，并恢复被中断的模型轮次继续生成后续结果；拒绝或重复消费不会执行。
- AC-018：HTTP 与 Electron 使用同一审批语义；审批状态、错误、工具结果及恢复轮次的事件/最终回答都能回写到当前工具调用卡片和对话 UI。

## 6. 风险与依赖

- 统一 MCP 执行可能改变错误包装和重试时机，需要保留兼容错误字段。
- 动态加载依赖模型能够先调用发现工具；兼容开关用于回退。
- URL 安全校验需要正确处理 IPv4、IPv6、DNS 解析和重定向；本期至少覆盖字面量内网地址与禁止协议。
- 未实现 OS 级沙盒，因此本期不能宣称对任意恶意代码提供强隔离。
