# Chat Wiki 知识链接产品规格

## 背景与目标

AI 在聊天中使用 Wiki 知识回答时，当前只能输出不可交互的文件路径或普通文本。需要建立稳定的 Wiki 知识链接协议，使用户可以从回答直接打开知识库中的对应文章。

## 用户与场景

- 用户在 Chat 中询问已配置 Wiki 知识库的内容。
- AI 查阅 Wiki 后，在回答中引用一个或多个知识页面。
- 用户点击引用链接，进入知识库页面并查看对应文章。

## 用户故事

- US-001：作为 Chat 用户，我希望回答中的 Wiki 引用可以点击，以便快速查看原文。
- US-002：作为 Chat 用户，我希望点击 Wiki 链接后直接定位到对应文章，而不是重新搜索文件。

## 范围

### 本次范围

- 定义 `mint-wiki://open?path=<encoded-relative-path>` 协议。
- 在 AI Wiki 使用规则中要求使用 Markdown 链接输出该协议。
- Chat Markdown 渲染器识别协议并跳转到 Wiki 页面。
- Wiki 页面支持从 URL 参数初始化并打开目标文件。
- 保持普通 HTTP、HTTPS、mailto、tel 链接行为不变。

### 非目标

- 不改变 Wiki 文件存储格式、路径结构或读取 API。
- 不把所有普通相对 Markdown 链接自动转换为 Wiki 链接。
- 不新增外部浏览器或 Obsidian 打开行为。

## 业务规则

- `path` 必须是 Wiki 根目录下的相对文件路径，优先使用 `pages/` 下的正式页面。
- `path` 使用 `encodeURIComponent` 编码，前端解析后只作为 Wiki 页面选择路径使用。
- 协议链接显示 AI 提供的 Markdown 链接文本；协议本身不暴露给用户。
- 协议路径为空、无法解析或目标文件不存在时，不执行跳转，并保留安全的不可点击文本表现。

## 验收标准

- AC-001：AI 输出 `[页面标题](mint-wiki://open?path=pages%2F主题%2F页面.md)` 时，Chat 中显示为可点击链接。
- AC-002：点击有效协议链接后，应用切换到 `/wiki`，Wiki 页面自动读取并展示对应文件。
- AC-003：中文、空格和嵌套目录路径经过编码后仍能正确打开。
- AC-004：无效协议、空 path 和不支持的协议不会触发 Wiki 跳转。
- AC-005：现有 Wiki 页面内部 Markdown 链接和 Chat 普通外链行为不回归。
- AC-006：服务端构建、客户端构建和相关测试通过。

## 风险与依赖

- 依赖 Wiki 页面已通过现有 `wiki:read` API 读取。
- 模型不遵守协议时，回答中的普通文本不会自动获得跳转能力；需要通过系统提示词约束输出格式。
- URL 参数属于导航状态，WikiPage 需要兼容浏览器和 Electron Hash Router。
