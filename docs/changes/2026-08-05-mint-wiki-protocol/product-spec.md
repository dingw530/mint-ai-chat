# Mint Wiki 统一链接协议产品规格

## 背景与目标

当前 Wiki 同时存在 Chat 专用的 `mint-wiki://` 链接和页面正文中的普通相对 Markdown 链接。不同模块对 `pages/...` 的解析基准不一致，导致 Wiki lint 将合法链接误报为 `pages/方法论/pages/概念/...`。

本变更将 `mint-wiki://open?path=...` 定义为 Wiki 页面引用的统一协议，并让客户端导航、服务端 lint、图谱建边和 Wiki 编译提示共享同一套路径语义。

## 用户与场景

- 用户在 Chat 中点击 AI 返回的 Wiki 页面引用。
- 用户在 Wiki 页面中点击另一篇 Wiki 页面链接。
- Agent 或 MCP 调用 Wiki lint 检查嵌套目录页面的链接健康状态。
- Wiki 摄入生成页面之间的关联链接，并由图谱提取页面引用关系。

## 用户故事

- US-001：作为 Chat 用户，我希望协议链接能稳定打开目标 Wiki 页面。
- US-002：作为 Wiki 用户，我希望页面正文中的协议链接不受当前页面目录影响。
- US-003：作为知识库维护者，我希望 lint 不再误报合法的跨目录链接。
- US-004：作为系统维护者，我希望 Chat、Wiki、lint、图谱使用同一套路径解析规则。

## 范围

### 本次范围

- 正式定义 `mint-wiki://open?path=<URL 编码的 Wiki 根目录相对路径>`。
- 统一协议路径的编码、解码、规范化和路径穿越校验。
- Wiki 页面和 Chat 支持协议链接，并保留旧版普通相对链接兼容行为。
- 服务内 `WikiLintTool` 与 MCP lint 解析协议链接，并修复 `pages/...` 根路径误判。
- 图谱链接提取和 Wiki 编译提示采用协议语义。
- 增加协议、lint、图谱和 UI 回归测试。

### 非目标

- 不改变 Wiki 磁盘目录结构、数据库 schema 或现有读取 API。
- 不使用 `file://` 暴露本地绝对路径。
- 不在本次变更中批量重写历史 Wiki 文件。
- 不新增新的 HTTP API endpoint。

## 业务规则

1. 协议固定为 `mint-wiki://open`，动作不是任意可执行命令。
2. `path` 必须是 Wiki 根目录下的相对路径；不得为空、以 `/` 开头或包含 `..` 路径段。
3. 协议路径经过 URL 解码后再做规范化和安全校验。
4. `pages/...`、`sources/...` 等 Wiki 根路径不再拼接当前页面目录。
5. 旧版 `./x.md`、`../x.md` 和 `pages/x.md` 普通链接继续兼容；其中 `pages/x.md` 按 Wiki 根目录解析。
6. 外部 HTTP、HTTPS、mailto、tel 链接保持原行为。
7. 无效协议或不安全路径不得触发导航、文件读取或图谱边创建。

## 验收标准

- AC-001：协议解析可处理中文、空格、嵌套目录和二次编码路径，并返回规范化 Wiki 相对路径。
- AC-002：Chat 中点击有效 `mint-wiki://open?path=...` 链接后，Wiki 页面展示目标文件。
- AC-003：Wiki 页面中点击协议链接后，目标解析不受当前页面所在目录影响。
- AC-004：空 path、绝对路径、路径穿越、错误 action 和非 `mint-wiki` 协议不会触发导航或读取。
- AC-005：服务内 lint 和 MCP lint 对嵌套页面中的 `pages/概念/目标.md` 不产生 `pages/当前目录/pages/...` 误报，并能识别真实断链。
- AC-006：图谱链接提取和 Wiki 编译生成规则识别统一协议，合法协议链接可以建立引用边。
- AC-007：现有 `./`、`../`、普通外链和已有 Chat Wiki 引用行为不回归。
- AC-008：相关单元测试、构建、Harness unit、coverage、boundary 和 UI browser AC 通过。

## 风险与依赖

- 依赖现有 `wiki:read` 路径安全校验和 `/wiki?path=` 导航。
- 历史页面仍可能使用普通链接，因此必须保留兼容解析。
- 统一协议会影响图谱和 lint 的链接识别，需覆盖旧格式和新格式的双向回归。
