# 产品规格：跨批次语义候选审核

## 背景与目标

当前跨批次页面主要依赖 `references` 连接，容易产生弱关联，同时相关主题仍可能形成孤岛。本变更将跨批次关系生成拆为候选筛选、AI 语义裁决和人工审核三步。主图只展示已采纳的正式边。

## 用户故事

- US-001：作为知识库维护者，我希望新页面能获得少量可解释的跨批次语义候选，而不是自动生成大量弱边。
- US-002：作为审核者，我希望查看候选的节点、关系、证据、置信度和来源，并决定采纳、拒绝或暂缓。
- US-003：作为图谱使用者，我希望主图只展示已采纳关系，避免候选边干扰阅读。

## 范围

### 本次实现

- FP-001：新页面与旧页面按标题、标签、正文关键词和分类筛选候选，每个新页面最多 3 个候选。
- FP-002：AI 仅审查候选对，输出本体内关系、证据和置信度。
- FP-003：候选持久化为 `graph_edge_candidates`，状态为 `pending | accepted | rejected | expired`。
- FP-004：提供候选列表、采纳、拒绝和跳过操作。
- FP-005：采纳候选时按主语义边规则去重后写入 `graph_edges`。

### 非目标

- 不为候选边绘制主图预览。
- 不引入向量数据库或 embedding 检索。
- 不自动采纳候选；本版本全部由人工采纳。

## 业务规则

| 规则 | 口径 |
|---|---|
| 候选范围 | 排除本批页面；每个新页面最多 Top 3 个旧页面；总候选分低于 0.25 不入候选。 |
| 泛词 | `AI`、`产品`、`工程`、`实践` 不可单独形成标签匹配。 |
| AI 可用关系 | `基于、导致、应对、应用于、约束、案例、区别于`。 |
| 证据 | 必须提供不超过 160 字的页面正文摘录；无法命中新旧任一页面正文则候选丢弃。 |
| 置信度 | 取值 0-1；低于 0.6 的候选不保存。 |
| 采纳 | 同一无序节点对已有正式语义边时拒绝采纳；否则写入正式边并将候选设为 `accepted`。 |
| 拒绝 | 状态设为 `rejected`，可保存不超过 500 字的审查说明。 |
| 跳过 | 不改变状态，保持 `pending`。 |
| 过期 | 创建满 30 天仍为 `pending` 的候选在查询时标记为 `expired`。 |

## 验收标准

- AC-001：一次摄入中，每个新页面最多产生 3 个跨批次候选，且候选分不低于 0.25。
- AC-002：候选仅包含允许关系、有效证据和 0.6-1 的置信度。
- AC-003：待审查候选不会出现在 `graph_edges` 或主图。
- AC-004：采纳后生成一条带 `strength=semantic`、证据、置信度和来源页面的正式边。
- AC-005：已有主语义边的节点对不能重复采纳。
- AC-006：审核界面可按状态查看候选，并支持采纳、拒绝、跳过。
- AC-007：30 天未审查候选显示为已过期，不能再采纳。
