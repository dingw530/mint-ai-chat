# 决策轨迹第一阶段：行动轨迹

## 背景与目标

当前聊天页可以接收 ReAct 运行事件，但用户看到的主要是思考文本和工具步骤，无法快速理解 AI 做了哪些可观察动作。第一阶段将现有事件转换为简短、可解释的行动轨迹，帮助用户理解回答生成过程。

## 用户与场景

- 用户在聊天中等待较长回答时，想知道 AI 当前正在做什么。
- 用户查看工具调用结果时，想区分“正在执行”“已完成”“失败重试”和“最终完成”。

## 用户故事

作为聊天用户，我希望在 AI 回复附近看到一条简洁的行动轨迹，从而了解 AI 做了哪些动作以及当前进度，而不需要阅读原始内部推理。

## 范围

- 做：基于已有 ReAct SSE 事件生成行动轨迹。
- 做：展示开始、轮次、工具动作、工具结果、重试/失败、循环检测和完成状态。
- 做：轨迹支持展开/收起，并复用现有显示 ReAct 步骤设置。
- 不做：展示原始 `thought`/reasoning 内容。
- 不做：展示工具原始参数和完整返回数据。
- 不做：将轨迹持久化到数据库或为历史消息补建轨迹。
- 不做：第一阶段生成模型判断依据、结论摘要或不确定性说明。

## 业务规则

1. 轨迹只消费可观察事件，不直接展示隐藏思维链。
2. 工具名称可展示；工具参数和原始工具结果不进入行动轨迹。
3. 工具摘要优先作为动作描述；无摘要时使用通用文案。
4. 重试事件显示“重试中”，最终失败显示“执行失败”。
5. 轨迹仅属于当前正在生成或刚完成的一次运行，切换会话时清空。
6. `showReactSteps=false` 时不展示行动轨迹。

## 验收标准

- AC1：普通无工具回答显示“开始分析”和“已完成回答”等轨迹状态。
- AC2：工具调用显示工具动作及完成状态，不显示参数或原始返回内容。
- AC3：工具重试、最终失败和循环检测均有对应状态文案。
- AC4：收到 `thought` 或 `reasoning` 事件时，行动轨迹不出现原始思考文本。
- AC5：关闭 ReAct 步骤展示设置后，行动轨迹不显示。
- AC6：客户端测试和项目构建通过。

## 风险与依赖

- 依赖现有 SSE 事件顺序和 `runId` 过滤。
- 当前轨迹不持久化，刷新页面或切换会话后不会恢复，这是第一阶段的明确限制。
- GitNexus CLI 在当前 Node 18 环境存在运行时兼容问题，影响分析需记录为降级验证。
