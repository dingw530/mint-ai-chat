## 背景与目标
- **业务背景**：Mint 的 wiki 知识库以文件树 + Markdown 方式管理知识文档，当前只能通过 chat 对话查询概念间的关系，缺乏可视化的全局关联视图。
- **当前问题**：用户需要了解多概念/方法论之间的关系（如"某个方法论的实现是哪些实践"），只能逐条通过 chat 查询，无法直观看到实体间的关联网络。
- **成功标准**：在 wiki 模块内新增"知识图谱"视图，用户可直观看到概念实体间的三元关系网络。

## 用户与场景
- **目标用户**：个人知识管理用户
- **典型场景**：用户打开 wiki 知识库 → 切换到"知识图谱"tab → 看到以力导向图展示的概念关系网络 → 点击节点查看详情

## 用户故事
- **US-001**：作为知识库用户，我希望在 wiki 页面中能看到知识图谱视图，从而直观了解概念之间的关联关系。
- **US-002**：作为知识库用户，我希望图谱中的节点可拖拽、可点击查看详情，从而交互式探索知识关系。
- **US-003**：作为知识库用户，我希望在摄入知识后图谱自动更新，从而不需要手动逐个添加节点和关系。

## 范围
### 本次要做
- **FP-001**：在 WikiPanel 中添加"文件浏览"/"知识图谱"tab 切换
- **FP-002**：实现力导向图可视化渲染（VGraph），支持节点拖拽、悬停高亮
- **FP-003**：后端图谱数据服务（节点/边的 CRUD、全量查询）
- **FP-004**：点击节点弹出详情面板（名称、类型、属性）
- **FP-005**：AI 工具 KnowledgeGraphTool，支持 AI 在对话中查询/添加图谱数据
- **FP-006**：摄入后自动构建图谱，每个 CompiledPage 创建一个 graph_node，同批次共享标签的页面间建立 shared_tag 边

### 本次不做
- ❌ 从 wiki 文件自动爬取提取三元组（数据通过 AI 辅助 + API 手动录入）
- ❌ 图谱编辑 UI（新增/删除节点/边通过 API 操作）
- ❌ 完整的节点分组/聚类/历史记录

## 约束
| 约束类型 | 具体限制 | 违反后果 |
|---------|---------|---------|
| 工程 | 集成在 wiki 模块内，不新增路由/导航入口 | 导航混乱 |
| 工程 | 不修改现有 wiki 文件浏览功能 | 回归风险 |
| 工程 | 可视化库选型：使用 VGraph（Canvas 图形引擎，内置力导向布局与交互行为） | 维护成本 |
| 兼容 | 无图谱数据时显示引导提示，不白屏 | 体验受损 |

## 数据模型与字段映射

### graph_nodes 表
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | TEXT (PK) | 节点唯一标识（UUID） |
| `label` | TEXT | 显示名称 |
| `type` | TEXT | 实体类型：'concept' \| 'practice' \| 'methodology' |
| `source_file` | TEXT (nullable) | 对应 wiki 文件路径（可选） |
| `properties` | TEXT (JSON) | 扩展属性，默认 `'{}'` |
| `created_at` | TEXT | ISO 8601 |
| `updated_at` | TEXT | ISO 8601 |

### graph_edges 表
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | TEXT (PK) | 边唯一标识（UUID） |
| `source_id` | TEXT (FK) | 主体实体 ID |
| `relation` | TEXT | 关系类型，如"包含实践"、"要求"、"属于" |
| `target_id` | TEXT (FK) | 客体实体 ID |
| `properties` | TEXT (JSON) | 关系属性，默认 `'{}'` |
| `source` | TEXT | 数据来源：'manual' \| 'auto-extracted' \| 'ai-generated' |
| `created_at` | TEXT | ISO 8601 |

## 验收标准
- [ ] **AC-001**：打开 wiki 页面，标题区显示"文件浏览"和"知识图谱"两个 tab，默认选中"文件浏览"
- [ ] **AC-002**：切换到"知识图谱" tab，图谱区渲染 VGraph 力导向图
- [ ] **AC-003**：图谱无数据时，显示"暂无图谱数据，可通过 AI 对话添加"引导提示
- [ ] **AC-004**：图谱节点可拖拽，力导向自动重新布局
- [ ] **AC-005**：点击节点，弹出详情面板显示名称、类型、属性
- [ ] **AC-006**：通过 API 新增节点 + 边后，刷新图谱可见
- [ ] **AC-007**：在 chat 中对 AI 说"把极限编程和持续集成加入图谱"，AI 批量创建两个节点
- [ ] **AC-008**：AI 批量创建时，每个节点都必须携带 sourceFile，缺少时给出错误提示
- [ ] **AC-009**：AI 批量创建节点和关系后，返回汇总信息（成功数 + 失败详情）
- [ ] **AC-010**：摄入知识（上传文件或 wiki_ingest 工具）完成后，自动为每个编译出的页面创建一个 graph_node
- [ ] **AC-011**：自动创建的节点 type 从页面所在分类目录推断（`pages/concept/` → `concept`），sourceFile 指向页面路径
- [ ] **AC-012**：同一摄入批次中，共享相同 tags 的页面之间自动建立 `shared_tag` 边，边的 source 标记为 `'auto-extracted'`
