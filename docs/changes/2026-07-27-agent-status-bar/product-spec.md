# Agent 状态栏

## 背景与目标

当前 ReAct 运行已经向前端发送轮次、工具调用、失败和循环检测事件，但模型上下文中没有统一的动态状态摘要，容易重复调用工具、遗忘运行预算或无法感知当前进度。本变更实现书中定义的 Agent 状态栏：由代码维护运行状态，在每轮模型调用前追加到上下文末尾，并将同一状态同步到聊天 UI。

## 用户故事

- 作为 Agent，模型每轮决策前都能看到当前轮次、工具计数、耗时、最近错误和循环保护状态。
- 作为聊天用户，我希望看到当前 Agent 正在第几轮、调用了多少次工具以及是否正在重试。
- 作为开发者，我希望状态摘要来自可验证的运行数据，而不是由另一个模型猜测。

## 范围

### 做

- 后端维护一次 ReAct 运行的状态快照。
- 每轮模型调用前追加一个 `<agent_status>` user 消息。
- 通过现有 SSE/IPC 共享链路发送 `agent_status` 事件。
- 前端展示当前轮次、工具调用数、当前工具、耗时和异常状态。
- 覆盖工具重试、循环检测、无工具回答和运行终态。

### 不做

- 不新增数据库表、迁移或 API 端点。
- 不把状态栏内容持久化为历史消息。
- 不新增 TODO 工具；没有可靠任务来源时不伪造 TODO 进度。
- 不展示模型隐藏思维链、工具完整参数或完整工具结果。

## 业务规则

1. 状态栏必须由服务端代码维护，不能由 LLM 汇总历史。
2. 状态栏使用 `user` 角色追加到上下文末尾，不修改 system prompt。
3. 一次运行只保留最新状态栏，避免陈旧状态误导模型。
4. 工具计数按工具名累计；重试次数和最终失败单独反映。
5. 状态栏包含简短操作策略：重复失败时切换方案，接近迭代上限时优先交付，检测循环时停止继续尝试。
6. UI 状态只属于当前运行，切换会话或开始新运行时清空。

## 验收标准

- AC-001：每次 ReAct 模型轮次的请求消息末尾包含最新 `<agent_status>`，且包含轮次、预算、工具计数和耗时字段。
- AC-002：状态栏不修改 system 消息，也不残留上一轮旧状态栏。
- AC-003：服务端通过现有 SSE/IPC 解析链路发送 `agent_status`，包含当前工具、工具计数、重试/错误和循环状态。
- AC-004：聊天 UI 在运行期间显示状态栏，能反映轮次、工具调用和终态；运行结束后显示完成状态。
- AC-005：普通回答、工具调用、重试失败、循环检测和取消路径均有自动化测试覆盖。
- AC-006：客户端/服务端测试、构建、Harness 检查和边界检查通过。

## 风险与依赖

- 依赖现有 `ReactEventEmitter`、SSE 解析器和 Electron IPC 复用链路。
- 当前工作区已有 `reactLoopCore.ts`、ReAct 测试和工具编排改动，本变更只做局部兼容修改。
- GitNexus CLI 在 Node 18 下不可运行，影响分析采用定向调用链审查和测试替代，并记录为验证降级。
