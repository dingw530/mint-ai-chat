# AgentRun 持久化与崩溃恢复产品规格

## 背景与目标

Mint 已完成进程内 AgentRun 事件契约：运行拥有稳定的 `runId`、严格递增的 `sequence`、工具状态、审批暂停和唯一终态。但 AgentRun 当前只存在于进程内，服务或 Electron 主进程重启后，运行轨迹、未完成工具和审批状态无法恢复，也无法判断一次工具调用是否已经产生副作用。

本变更为 AgentRun 增加最小可用的持久化事件日志、Reducer 恢复和中断诊断能力。目标是：进程中断后可以从事件重建运行快照，明确标记未完成工具为未知结果，并为后续显式恢复/人工决策提供安全基础；不在本变更中自动重放工具或恢复模型执行。

## 用户与场景

- 用户的 Agent 运行因服务重启中断后，系统不会把未确认的工具当作成功，也不会盲目再次执行副作用操作。
- 开发者可以根据 `runId` 和 `sequence` 重建中断前的阶段、轮次、工具和审批状态。
- 评测维护者可以注入进程中断，验证恢复结果和幂等边界，而不依赖 SSE 文本。

## 用户故事

- US-001：作为用户，我希望中断的工具调用被明确标记为未知，而不是被错误地当成成功或自动重放。
- US-002：作为开发者，我希望可以从持久化事件重建 AgentRun 快照和最后一次有效序列。
- US-003：作为维护者，我希望重复恢复、重复写入和损坏事件不会产生重复工具执行或静默修复。

## 范围

### 做

- 增加 AgentRun 持久化事件存储，采用 SQLite migration 和追加写入。
- 为运行开始、工具开始/结束、审批、终态等恢复所需事件定义持久化白名单和版本。
- 增加从事件重建快照的纯 Reducer。
- 增加中断运行扫描：未完成工具生成 `tool_outcome_unknown` 诊断，运行进入可审计的中断结果。
- 保证同一 `runId` 的持久化序列连续、唯一、不可覆盖。
- 增加持久化、恢复、损坏、重复写入和副作用安全测试。

### 不做

- 不自动重放任何工具调用。
- 不在本变更增加公开 HTTP、Electron IPC 或 MCP endpoint。
- 不改变现有 SSE、IPC、客户端 reducer、A2UI 和最终消息持久化行为。
- 不实现跨设备运行接管、lease、会话分支或完整历史回放 UI。
- 不把工具原始参数、完整结果、API key 或其他敏感内容原样写入事件日志。
- 不修改插件体系和 Cordis 集成。

## 业务规则

- 每个持久化事件属于一个 `runId`，`sequence` 从 1 开始严格递增。
- 终态事件只能是 `completed`、`failed` 或 `cancelled` 之一；终态之后不能追加运行事件。
- 已有终态的 run 不参与中断恢复扫描。
- `tool_call_started` 没有对应完成、失败或取消事件时，恢复结果必须标记为 `tool_outcome_unknown`。
- 未知工具结果不得自动转换为成功，不得自动重新执行原工具。
- 相同 `runId + sequence` 只能写入一次；相同事件重试必须幂等，内容冲突必须失败。
- 事件日志损坏、序列断裂或未知必需事件类型必须 fail closed，不能静默修复。
- 持久化事件只保存恢复所需的安全字段；实时 ReactEvent 仍可向订阅者发送完整的当前语义。

## 验收标准

- AC-001：运行事件可以按 `runId` 追加持久化，并在重新加载后按原顺序重建快照。
- AC-002：持久化层拒绝序列跳号、终态后追加和同序列内容冲突；相同事件的幂等重试不会重复写入。
- AC-003：运行在工具执行中中断后，恢复结果包含对应 `callId` 的 `tool_outcome_unknown`，且不会执行该工具。
- AC-004：已完成、失败或取消的 run 不会被重复恢复；恢复扫描可重复执行且结果稳定。
- AC-005：损坏 JSON、未知必需事件类型和非法事件状态均明确失败，不生成误导性快照。
- AC-006：API key、authorization、cookie、原始工具参数和完整工具结果等敏感字段不会进入持久化 payload。
- AC-007：现有 AgentRun 实时事件、审批流程、SSE/IPC 传输、客户端行为和最终消息持久化回归通过。
- AC-008：数据库 schema 仅通过 migration 增加；服务端类型检查、定向测试、coverage、boundary 和完整 Harness 验证通过。

## 非功能要求

- NF-001：事件 Reducer 为纯函数，恢复不依赖 Express、Electron、React 或 Sink。
- NF-002：持久化写入失败必须阻止该事件被视为已提交，不能出现内存序列与持久化序列静默分叉。
- NF-003：恢复过程不得自动触发任何工具副作用或模型调用。
- NF-004：事件 schema 带有版本字段，未来新增事件类型必须显式兼容或拒绝。

## 风险与依赖

- AgentRun 和 ReactEvent 的上游影响面为 CRITICAL；必须保持现有实时发布路径，并通过适配器接入持久化。
- SQLite 写入会增加每个运行事件的同步 I/O；第一版只持久化恢复白名单，不保存 token delta 和完整文本增量。
- 现有工作区存在用户已有的 AGENTS、Skill 和 Harness 产物改动；本变更不得覆盖或清理这些文件。
- 若实施中需要自动恢复模型轮次、公开 endpoint 或工具重放，必须暂停并扩展 Spec。
