## 背景与目标

**问题**：当前摄入后自动建边机制（`shared_tag`）在实际运行中产生 0 条边。数据库 149 条边全部来自 AI 对话中手动调用 KnowledgeGraphTool，自动建边形同虚设。

**根因**：
1. AI 编译时会将一篇文章拆成多个 CompiledPage（主页面 + 子概念），子概念标签为空或唯一，不满足 shared_tag 建边条件
2. `shared_tag` 只覆盖"同批次、同标签"这一种关系信号，过于单一
3. 跨批次页面即使共享标签，也不会被连接

**目标**：将自动建边从单一标签匹配升级为**多层内容分析**，让图谱在每次摄入后自动生成有意义的边。

## 变更的用户故事

- **US-003（更新）**：作为知识库用户，摄入知识后图谱自动更新为有意义的关联网络，而非只有孤立的节点。
- **US-004（新增）**：作为知识库用户，我希望相关概念之间自动建立语义关系（如"包含""基于""属于"），从而直观看到知识结构。

## 变更范围

### 本次要做
- **FP-007**：AI 编译时输出页面间语义关系（扩展 compileSource 输出结构）
- **FP-008**：子概念自动挂载到父页面（同源 content 包含检测）
- **FP-009**：交叉引用链接提取（从 markdown 正文解析相对路径链接）
- **FP-010**：跨批次内容相似度连接（TF-IDF 余弦相似度）
- **FP-011**：关系名规范化（LLM 输出的关系归一到预定义集合）
- **FP-012**：回溯脚本——对已有 95 个节点重新建边

### 本次不做
- ❌ 图谱编辑 UI（保持通过 API / AI 工具操作）
- ❌ 前端关系筛选/过滤 UI（图谱仅展示全部网络，不新增过滤控件）

## 变更的验收标准

- [ ] **AC-013**（替代 AC-012）：同批次摄入的页面之间，AI 自动输出语义关系并正确入库
- [ ] **AC-014**：同源文档产生的子概念节点自动建立 `part_of` 边挂载到父页面
- [ ] **AC-015**：页面正文中包含指向其他 wiki 页面的相对链接时，自动建立 `references` 边
- [ ] **AC-016**：新页面摄入后，与已有页面内容相似度 > 阈值的自动建立 `related_to` 边
- [ ] **AC-017**：LLM 输出的关系名经过规范化，同一语义不会出现不同名称的边
- [ ] **AC-018**：回溯脚本运行后，原有孤立节点全部连接到图谱中

## 预定义关系类型集合

| 关系类型 | 含义 | 示例 | 来源 |
|---|---|---|---|
| 包含 | 整体→部分，父→子概念 | Harness Engineering → 状态文件驱动 | LLM / 算法 |
| 属于 | 子类→父类，实例→类别 | Spec编写指南 → SDD | LLM |
| 基于 | 依赖/引用/前提 | SDD → 需求分析 | LLM |
| 区别于 | 对比/区分 | SDD → TDD | LLM |
| 演进到 | 时序/版本演进 | Vibe Coding → 渐进式SDD | LLM |
| 提供 | 提供能力/输出 | PrismSpec → Plan Mode | LLM |
| 实现 | 实现/达成 | 持续集成 → 自动构建 | LLM |
| 支持 | 辅助/支撑 | 知识库 → 上下文注入 | LLM |
| 定义 | 定义/规范 | 验收标准 → 完成定义 | LLM |
| part_of | 内容来源归属（子概念挂载） | 七个核心工程原则 → Harness Engineering | 算法 |
| references | 交叉链接 | 页面A → 页面B（A正文中有B的链接） | 算法 |
| related_to | 内容相似（跨批次宽泛连接） | 新页面 → 已有相似页面 | TF-IDF |

来源列：LLM = AI 编译时输出，算法 = 代码分析自动生成，TF-IDF = 相似度计算。
