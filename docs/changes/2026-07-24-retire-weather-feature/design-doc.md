# 设计文档：移除天气功能

## 方案

1. 删除天气专属实现文件和端点注册，避免运行时仍能发现或调用天气能力。
2. 从工具注册表、Agent 列表和前端 Agent 选择逻辑中移除天气分支。
3. 新增数据库迁移 `retire-weather-agent`，先解除 `conversations.locked_agent`，再删除 `agents.id = 'weather'`。
4. 更新部署说明、安全说明、环境变量说明和 Electron endpoint manifest。
5. 将天气专属测试改为通用 Agent/外部数据测试，保留路由、工具、SSE 和数据库行为覆盖。

## 兼容性与风险

- 已有数据库通过迁移兼容；天气锁定会话不会继续引用已删除 Agent。
- 历史文档保留天气功能的历史记录，不代表当前运行时仍提供该能力。
- 用户输入天气相关问题仍可作为普通文本交给通用模型处理，但不再触发专属工具或 Agent。
