# 产品规格：工具调用上限优化

## 背景与目标

ReAct 循环引擎的迭代上限为 20（默认 5），Wiki 知识库查询涉及多轮工具调用（搜索→读取→再搜索→再读取），容易耗尽迭代次数而无法得到最终答案。

**目标**：将 Wiki 查询场景的迭代消耗从 5-10+ 轮降至 1-3 轮。

## 用户故事

- US-001: 作为用户，我希望一次 Wiki 查询就能获得完整答案，不需要等待多轮工具调用
- US-002: 作为用户，我希望 AI 不会在知识库中反复搜索相同内容浪费时间

## 功能点

- FP-001: 增强 wiki_query 返回内容，从 200 字符 snippet 扩展为更大上下文块
- FP-002: 添加 System Prompt 引导，指导 AI 高效使用 Wiki 工具
- FP-003: 循环检测机制，检测重复工具调用并强制打断
- FP-004: 合并 wiki_query + list_files + read_file 为复合 wiki_search 工具

## 验收标准

- AC-001: wiki_query 单次返回的 snippet 上下文块不少于 2000 字符（或全文，取较小值）
- AC-002: System Prompt 包含 Wiki 工具使用指南，引导 AI 减少不必要的工具调用轮次
- AC-003: 连续 3 轮相同工具名+相似参数（编辑距离 < 30%）的调用被检测并打断
- AC-004: wiki_search 工具可一次完成搜索+读取，替代原三个独立工具
- AC-005: 旧工具（wiki_query/list_files/read_file）从注册表移除
- AC-006: Wiki 查询场景迭代消耗 ≤ 3 轮（对比优化前 5-10+ 轮）

## 非目标

- 不改变 ReAct 循环的迭代上限配置（保留 maxIterations 设置）
- 不引入 embedding 向量检索
- 不改变 Wiki 文件的存储格式

## 精简模式说明

本需求为内部工具优化，功能点 4 个、路径明确、无跨团队依赖，启用精简模式。
