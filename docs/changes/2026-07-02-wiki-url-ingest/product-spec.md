## 背景与目标
- 当前 `wiki_ingest` 已支持 `urls` 入参，但实际抓取仍主要依赖服务端 HTTP 请求。对于依赖前端渲染或反爬策略的页面，普通抓取经常拿不到正文，用户只能先在浏览器中打开，再手动另存为 HTML 上传。
- 目标：当知识摄入输入为 URL 时，优先在 Electron 内置浏览器中加载页面并抽取可见正文，再复用现有 `wiki_ingest` 编译链路完成知识入库，减少“先浏览器访问、再本地保存、再上传”的手工步骤。
- 结果预期：公开网页、JS 渲染网页和部分在 Electron 内置浏览器中可访问的页面可以直接摄入，用户得到更短的知识收集路径。

## 用户与场景
- 目标用户：使用 Mint 的个人用户或小团队用户，在聊天或工具调用中向知识库摄入网页内容。
- 典型场景：
  - 用户给出一篇公开文章 URL，希望直接入库。
  - 用户给出需要前端渲染后才显示正文的页面 URL，希望系统自动等待渲染完成再摄入。
  - 用户遇到普通 HTTP 抓取失败的页面，希望系统退回到内置浏览器抓取而不是要求手动保存网页。

## 用户故事
- US-001：作为知识库用户，我希望把 URL 直接传给 `wiki_ingest`，由系统自动抓取页面正文并编译入库，而不是手动保存 HTML 后再上传。
- US-002：作为知识库用户，我希望对于需要前端渲染的网页，系统能在 Electron 内置浏览器中加载并抽取正文。
- US-003：作为知识库用户，当 URL 摄入失败时，我希望得到清晰的失败原因，便于判断是页面不可访问、超时、内容为空还是仍需手动处理。

## 范围
### 本次包含
- `wiki_ingest.urls` 的页面摄入行为增强
- Electron 内置浏览器加载页面并抽取正文
- 复用现有 `parseFile` / `ingestWikiSource` 编译链路
- 普通 HTTP 抓取失败后的降级处理

### 本次不包含
- 复用 Chrome 系统浏览器的 cookie 或登录态
- 自动登录、验证码绕过、反爬对抗
- 跟随页面中的站内链接做网页爬虫式展开
- 截图、导出 PDF、批量多页抓取
- 新增独立的 URL 摄入 UI

## 业务规则
- BR-001：`wiki_ingest` 仍然以 `urls` 作为 URL 输入入口，不新增独立工具名。
- BR-002：仅支持 `http` / `https` URL。
- BR-003：每个 URL 只抓取当前页面正文，不展开站内链接。
- BR-004：优先使用 Electron 内置浏览器加载页面并抽取正文；若 Electron 运行环境不可用，则回退到现有服务端 HTTP 抓取。
- BR-005：若内置浏览器抓取失败，再回退到现有 `browserFetch`，最后再回退到 `curl`。
- BR-006：抓取成功后，页面内容必须进入现有 `parseFile` / `buildWikiSourceText` / `ingestWikiSource` 链路，不新增第二套编译入口。
- BR-007：若抓取结果为空、超时、非 HTML、或多次降级后仍失败，必须返回可读错误信息。

## 验收标准
- AC-001：用户向 `wiki_ingest` 传入一个公开网页 URL 时，系统可直接摄入正文并生成 Wiki 页面。
- AC-002：用户向 `wiki_ingest` 传入一个需要 JS 渲染的页面 URL 时，系统可在 Electron 内置浏览器完成加载后摄入正文。
- AC-003：用户向 `wiki_ingest` 传入一个普通 HTTP 抓取失败但在内置浏览器中可访问的页面时，系统可通过内置浏览器完成摄入。
- AC-004：当 Electron 运行环境不可用时，现有 URL 摄入行为保持可用，不影响非桌面或开发环境。
- AC-005：当 URL 抓取失败时，错误信息能说明失败阶段，例如超时、加载失败、空内容或内容类型不支持。

## 术语与统一口径
- “内置浏览器”：指 Electron 进程中的隐藏 `BrowserWindow`，不是外部 Chrome。
- “正文”：指页面中用户可见且可用于知识摄入的主要文本内容，不包含脚本、样式和无关装饰内容。
- “摄入成功”：指页面内容已进入 `wikiIngestionService` 并完成 source 文件、page 文件和 manifest 记录。

## 风险与依赖
- 依赖：Electron 主进程可创建隐藏窗口并执行页面脚本；现有 `parseFile` 能正确处理抓取到的 HTML 内容。
- 风险：部分网页仍可能要求外部浏览器登录态或更强的反爬校验，本次版本不覆盖此类场景。
- 风险：内置浏览器抓取比纯 HTTP 更重，需控制超时与资源占用。

## 反例
- 反例-001：用户认为“只要把 URL 传进来，所有公众号都一定能抓到”。正确结果：只能覆盖 Electron 内置浏览器中可访问的页面，外部浏览器登录态不在本次范围内。
- 反例-002：用户认为“URL 摄入等于网页爬虫”。正确结果：本次只抓单页正文，不展开链接、不做站点爬取。
- 反例-003：用户认为“抓取失败就默默回退并假装成功”。正确结果：如果多级降级后仍失败，必须显式返回错误原因。
