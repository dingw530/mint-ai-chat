## 背景与目标

当前记忆机制将所有记忆作为平面文本全量注入上下文，并在每次有价值消息后直接 fire-and-forget 调用一次 LLM 提取。它能完成基础回忆，但无法可靠处理跨会话检索、信息更新、主体消歧、历史事件回溯和主动关联。

本变更的目标是建立“结构化长期画像 + 可检索情景记忆 + 可恢复后台整理”的第一阶段基础，使记忆在数量增长后仍保持可控、可解释和可更新。

## 用户与场景

- 用户在不同会话中分别提供个人资料、偏好和项目背景，后续对话能够准确引用最新有效信息。
- 用户修改事实时，系统更新旧事实并保留可追溯历史，而不是产生互相矛盾的并列文本。
- 用户询问过去某次讨论、决策或事件时，系统按需检索相关对话细节，不加载全部记忆。
- 记忆提取服务暂时不可用或应用重启时，已完成的对话不会丢失，任务可重试。

## 用户故事

- US-101：作为用户，我希望同一事实的后续修改能替换当前有效记忆并保留历史版本。
- US-102：作为用户，我希望系统区分用户本人和家人等不同主体，避免记忆串用。
- US-103：作为用户，我希望回答只加载与当前问题相关的记忆，避免历史信息污染上下文。
- US-104：作为用户，我希望记忆提取失败后能够重试，而不影响当前聊天。
- US-105：作为用户，我希望知道记忆来自哪次对话、当前是否有效以及为什么被更新。

## 范围

### 本次要做

- FP-101：扩展记忆数据模型，支持 key/value、主体、来源、置信度、有效状态和版本关系。
- FP-102：将提取结果改为结构化记忆操作，至少支持 ADD、UPDATE、NOOP；DELETE 通过失效标记实现。
- FP-103：实现按 key、主体和关键词的候选记忆检索，优先使用 SQLite FTS5/可解释的文本检索。
- FP-104：将回答侧从全量记忆注入改为“小型 active profile + 按需相关记忆”。
- FP-105：建立持久化后台记忆任务，支持 pending、processing、completed、failed、重试和幂等。
- FP-106：为新记忆链路补充基础回忆、多会话更新、冲突和故障恢复测试。

### 本次不做

- 不实现 User-as-Code 或任意 LLM 生成代码执行。
- 不实现知识图谱、复杂实体关系推理或自动主动服务规则引擎。
- 不引入外部向量数据库；向量 embedding 和 reranker 延后到检索基线验证后。
- 不改变现有 memories CRUD 端点的基本兼容行为。
- 不在本阶段实现上下文感知分块的完整 LLM 索引流水线；只预留情景记忆和索引字段。

## 业务规则

- BR-101：每条 active 记忆必须有稳定的 `memory_key` 和 `subject`；无法确定时使用 `general` 和 `user`，不得丢弃原文。
- BR-102：同一 `memory_key + subject` 的新事实必须先与现有候选对账，再决定 ADD、UPDATE 或 NOOP。
- BR-103：UPDATE 不物理删除旧记录；旧记录变为 superseded，并记录替代关系。
- BR-104：只有 active 且通过检索/重要性筛选的画像记忆可以进入回答上下文。
- BR-105：后台任务必须持久化状态；同一 conversation 不得并发创建重复处理任务。
- BR-106：记忆处理失败不得影响 SSE 主聊天；失败任务按有限次数退避重试并保留错误原因。
- BR-107：敏感字段不得写入普通错误日志；来源和用户可见的记忆内容仍应支持手动删除。

## 验收标准

- AC-101：输入“我住在北京”后产生 active 记忆；随后输入“我已经搬到上海”，当前查询只返回上海，且北京记录可查为 superseded。
- AC-102：分别记录“用户本人喜欢咖啡”和“用户父亲对咖啡过敏”，查询用户偏好时不得返回父亲的健康事实。
- AC-103：已有 200 条记忆时，普通问题的注入内容只包含 profile 必要项和相关检索结果，不再全量拼接 200 条。
- AC-104：同一对话重复提交任务不会产生两次有效更新；任务失败后重试不会产生重复 active 记忆。
- AC-105：数据库重启或服务进程重启后，pending/failed 任务仍可被恢复处理。
- AC-106：历史事件查询能够返回来源对话和原始内容片段，且不要求把所有历史记忆注入 prompt。
- AC-107：现有记忆管理面板的列表、编辑、删除和手动创建行为保持兼容。
- AC-108：记忆处理失败、检索为空、旧数据缺少新字段时，聊天主流程仍能正常完成。

## 非功能性需求

- NF-101：记忆读取为同步本地查询，普通请求不新增远程 LLM 调用。
- NF-102：后台任务有明确超时、重试上限和失败状态，不能无限循环。
- NF-103：新字段必须通过 migration 增加，不能直接修改已有用户数据库结构。
- NF-104：所有自动生成记忆保留来源 conversation/message 标识，便于审计和删除。
- NF-105：结构化解析失败时必须安全降级为“不更新”，不得执行未经验证的 SQL 更新。

## 风险与依赖

- LLM 可能错误判断更新关系；通过候选对账、置信度、历史版本和用户可编辑性降低影响。
- 旧数据没有结构化 key；迁移期需兼容旧 content，并允许后台渐进回填。
- SQLite FTS5 的中文分词能力有限；首阶段保留关键词/分类过滤接口，后续再评估 embedding。
- 后台任务与现有作业系统的复用方式需在设计和实现阶段确认。
