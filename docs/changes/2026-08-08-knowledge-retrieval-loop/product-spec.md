# 产品规格：知识检索闭环

## 背景与目标

Mint 已支持 SQLite FTS5 与 sqlite-vec 的混合检索，但结果仍以 chunk 为内部候选，历史页面不一定已经完成向量化，Chat 中的来源卡片也没有把“为什么命中”讲清楚。本变更把检索、索引维护和回答引用串成一个知识库闭环，同时保持 `/chat` 为主工作区。

目标：

- 同一页面在最终检索结果中只出现一次，并保留最优证据 chunk。
- 让已有知识库可以分批向量回填，能看到进度、覆盖率、失败项并重试。
- 让 Chat 回答沿用现有 A2UI 引用协议，展示标题、章节、证据片段和关键词/语义命中类型，并可跳回 Wiki。

## 范围

包含：混合检索页面聚合、向量索引清理、回填任务与健康度 API/界面、A2UI 来源模型和 Chat 来源卡片增强、历史 v1 block 兼容、测试和浏览器验收。

不包含：更换 embedding 模型、引入外部向量数据库、重做 Chat 页面信息架构、独立检索后台。

## 用户故事

- 作为使用知识库问答的人，我希望同一页面不会重复出现，并能知道回答依据的具体章节和片段。
- 作为知识库维护者，我希望在 `/wiki` 看到向量覆盖率和健康状态，并能启动/重试回填。
- 作为离线或本地 embedding 服务用户，我希望服务短暂失败时关键词搜索与已有 Chat 引用仍可工作。

## 验收标准

- AC-001：关键词与向量候选合并后，同一 `sourcePath` 最终最多返回一个页面结果；结果保留最佳 chunk 的 heading/snippet，并保留该页面的 lexical/vector 命中信息。
- AC-002：向量回填支持全量、路径前缀和选中页面范围，返回任务进度，并对单页失败继续处理；失败任务可以重试。
- AC-003：Wiki 管理区显示文档/chunk 总数、已向量化数、覆盖率、待处理数、失败数和孤儿向量数，并显示当前模型与维度。
- AC-004：Chat 回答中的现有 A2UI 来源引用展示 `[C#]`、标题、章节、证据片段、关键词/语义标签和页面状态；点击可打开对应 Wiki 页面。
- AC-005：已有 `wiki_source_reference` v1 持久化 block 可以继续渲染；新字段缺失时使用兼容默认值。
- AC-006：embedding 服务不可用时，FTS5 结果和 A2UI 来源引用链路继续可用，并记录降级日志。

## 约束与完成定义

- 新 API 使用 `server/endpoints/` 声明式注册；数据库结构使用 migration。
- `/chat` 仍是回答入口，向量维护只作为 `/wiki` 知识维护能力暴露。
- 完成定义：局部测试、服务端全量测试、客户端测试、构建、Harness unit/coverage/boundary/browser-ac 均通过，且追溯记录有证据。
