# PP-013：首次启动与模型连接引导

## 背景与目标

Mint 当前默认进入 Chat。新安装没有模型端点时，用户可以输入并发送消息，随后才看到 `API URL or API Key not configured`；发送路径还可能先创建一个没有有效回答的会话。模型端点配置也分散在通用设置和模型端点两个入口中。

本变更的目标是让用户在首次启动时明确知道如何连接自己的模型，并在不配置模型时仍可安全浏览应用。首次使用成功定义为：用户主动发送消息，AI 回复完整生成、无错误，并成功保存到会话。

## 用户与场景

- 新安装且没有通过连接测试的文本模型端点的个人用户。
- 已跳过首次引导、之后仍没有模型端点的用户。
- 已保存并通过测试的端点在实际请求时发生网络、鉴权、模型或未知错误的用户。
- 使用标准服务商、代理地址、OpenAI 兼容服务或无需 Key 的本地模型服务的用户。

## 用户故事

- US-001：作为新用户，我希望首次启动时看到清晰的模型连接入口，以便不用先发送失败消息才能开始使用。
- US-002：作为暂时不配置模型的用户，我希望跳过引导并浏览其他页面，但 Chat 明确不可用。
- US-003：作为模型配置用户，我希望填写 URL、可选 Key、API 类型和模型，并用真实请求验证配置。
- US-004：作为请求失败的用户，我希望看到可理解的错误分类，重试时不重复创建相同用户消息，配置错误时能回到已填充的修复路径。

## 功能范围

### FP-001 首次引导状态

1. 首次启动且不存在“连接测试成功并保存”的文本端点时，显示阻塞式全屏引导。
2. 引导提供“连接模型”和“跳过”两个明确动作；用户必须完成其中一个。
3. 点击“跳过”立即记录已完成首次引导，进入 Chat；其他导航保持可用，Chat 输入区禁用并显示“连接模型后开始对话”。
4. 后续启动不再强制引导；升级用户已有历史会话时按非首次使用处理。无可用端点时仅在 Chat 内提示。跳过后的默认落点为 Chat。

### FP-002 统一模型连接

1. “连接模型”进入唯一的模型连接界面，不要求用户在通用设置和模型端点之间寻找入口。
2. 界面始终显示可编辑 URL；API Key 可为空，空值时请求不得发送鉴权头。
3. API 类型提供 `Chat Completions`（默认）、`Responses`、`Anthropic Messages`。
4. 模型支持自由输入；填写服务商、URL、Key 后尝试拉取模型列表，列表失败不阻塞手动输入。
5. 用户必须明确选择或输入模型后才能测试连接；不自动选择模型列表第一项。
6. 连接测试使用固定的最小提示词和受限输出长度，真实调用模型，不创建会话、不写入聊天记录，并提示可能产生少量费用。
7. 测试成功后保存配置并返回 Chat，不提前创建会话，也不额外显示“已连接”。
8. API Key 只以脱敏形式展示，错误和日志不得泄露完整 Key；编辑时不回显完整 Key。
9. 通用设置不展示或保存文本/图片模型的 URL、API Key、API 类型和模型 ID；模型连接配置统一在模型端点中创建或编辑。

### FP-003 首条消息与失败恢复

1. 具有成功验证记录的端点允许用户发送消息；会话只在真实发送时创建。
2. 首条回复必须完整生成、无错误且成功持久化，才记录首次成功事件。
3. 已保存配置但实际请求失败时创建会话并标记失败，展示错误信息，保留原始用户消息。
4. 网络断开、超时、服务端 `5xx`、限流 `429` 允许用户主动重试；重试复用原用户消息，不重复创建用户消息记录。
5. `401/403`、`404`、参数不兼容进入修复连接；未知错误同时提供“重试”和“检查连接”。
6. 修复界面预填当前配置并保留错误上下文；测试成功后返回原失败消息，用户可继续重试。

## 非目标

- 不负责模型回答质量评估、默认模型策略、多模型切换或 fallback。
- 不负责文档导入、Wiki 构建、来源问答或 Wiki 空状态行动化；这些由 PP-015、PP-016 负责。
- 不负责账号、云同步、远程分析或跨设备引导状态。
- 不负责自动修复错误配置；修复必须由用户修改并重新测试。

## 业务规则

| ID     | 规则                                                                                           |
| ------ | ---------------------------------------------------------------------------------------------- |
| BR-001 | “可用端点”只表示该端点存在最近一次成功连接测试并已保存的验证记录；启动时不发起模型请求。       |
| BR-002 | 环境变量或预置配置也必须经过真实连接测试，不能仅因存在配置而判定可用。                         |
| BR-003 | URL 始终可编辑；模型列表是辅助能力，无法获取时允许手动模型 ID。                                |
| BR-004 | 连接测试成功才保存/更新端点的验证记录；失败保留表单输入但不得覆盖已有可用配置。                |
| BR-005 | 连接测试不得创建会话或聊天消息；真实用户发送失败则按 FP-003 创建失败会话。                     |
| BR-006 | 首次引导跳过状态与端点验证状态独立保存；跳过不会让 Chat 可用。                                 |
| BR-007 | 3 分钟指标分母只包含点击“连接模型”的用户；跳过率单独记录，不设目标上限；两项首版均只建立基线。 |

## 验收标准

- **AC-001**：清除引导状态和端点数据后访问应用，出现阻塞式全屏引导；页面提供“连接模型”和“跳过”，不能直接使用 Chat 输入框。
- **AC-002**：点击“跳过”后落到 Chat，输入框禁用并显示“连接模型后开始对话”，其他导航仍可访问；刷新后不再出现全屏引导。
- **AC-003**：在连接界面填写 URL、可选 Key、API 类型和模型；API 类型包含三项且默认 Chat Completions，URL 可编辑，Key 可为空且模型支持手动输入。
- **AC-004**：模型列表请求成功时提供选择；模型列表请求失败时仍允许手动填写模型并继续连接测试。
- **AC-005**：连接测试发起一次真实最小模型请求；成功后保存端点验证记录、返回 Chat、启用输入框，且测试不创建会话或聊天消息。升级数据若缺少验证记录，当前激活的文本端点仍作为兼容连接配置。
- **AC-006**：首次真实消息完成完整无错误回复并成功保存后，用户消息与助手消息出现在会话中，且记录首次成功事件。
- **AC-007**：无端点时不发送真实消息、不自动创建会话；已有验证端点但请求失败时创建失败会话并展示错误，保留原消息。
- **AC-008**：网络类错误显示重试操作；重试复用原用户消息，不重复新增用户消息；鉴权、模型不存在或参数不兼容显示修复入口。
- **AC-009**：进入修复入口时表单预填配置并显示错误上下文；修复测试成功后回到原失败消息并可重试。
- **AC-010**：API Key 持久化后只展示脱敏值；空 Key 请求省略鉴权头；错误提示和日志不包含完整 Key。
- **AC-011**：本地记录引导展示、跳过、模型列表结果、测试结果、首条消息和首条成功回复耗时；不上传用户内容。
- **AC-012**：打开设置的通用设置时不显示模型连接配置字段；进入模型端点并编辑端点时仍可配置 API URL、API Key、API 类型和模型 ID；保存通用设置不会覆盖端点模型配置。

## 指标

- `first_use_onboarding_shown`、`first_use_onboarding_skipped`。
- `model_list_loaded`、`model_list_failed`。
- `connection_test_started`、`connection_test_succeeded`、`connection_test_failed`（含错误分类）。
- `first_message_sent`、`first_response_completed_saved`。
- 从引导展示到首条成功回复的耗时；3 分钟成功率仅对点击连接模型的用户建立基线。
- 引导跳过率独立记录，不设置首版目标上限。

## 风险与依赖

- 不同协议的模型列表能力不一致，必须保留手动输入兜底。
- 真实连接测试可能产生费用，需在界面明确提示并限制输出长度。
- 现有会话发送链路会在请求前自动创建会话；需要改造为能区分未配置阻断和已配置运行时失败。
- 端点验证状态需要数据库迁移；旧端点在重新测试前不能被判定为已验证可用。
- 本地事件只用于建立基线，不代表远程产品分析能力。
