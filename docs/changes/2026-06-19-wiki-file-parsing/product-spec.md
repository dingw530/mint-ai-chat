## 背景与目标
- **业务背景**：LLM Wiki 知识库当前仅支持 URL 抓取和纯文本输入两种方式摄入资料，限制了用户将本地文件快速导入知识库的能力。
- **当前问题**：用户积累了大量的 HTML 文档、TXT 笔记、Markdown 文件和 PDF 技术文档，需要手动粘贴内容或寻找第三方转换工具才能导入 Wiki，使用门槛高、效率低。
- **成功标准**：用户可直接上传 HTML/TXT/MD/PDF 文件到知识库，系统自动解析文本内容并进入 Wiki 编译流程，原始文件存档可查。文件大小限制可配置，大文件友好拒绝。

## 用户与场景
- **目标用户**：使用 Mint · 清言 知识库功能的终端用户
- **典型场景**：用户在本地有技术文档（PDF/HTML/MD/TXT），希望一键导入到个人 Wiki 知识库，由 AI 自动编译为结构化页面

## 用户故事
- **US-001**：作为知识库用户，我希望在聊天中上传 HTML/TXT/MD/PDF 文件后调用 wiki_ingest，从而将文件内容自动解析并编译到 Wiki 知识库。
- **US-002**：作为知识库用户，我希望在 Wiki 面板中直接上传文件，从而在浏览知识库时就能完成资料导入。
- **US-003**：作为知识库用户，我希望上传的原始文件被存档在 sources/ 目录下，从而随时回溯原始内容。
- **US-004**：作为知识库管理员，我希望文件大小限制可配置，从而根据服务器资源灵活调整。

## 范围
### 本次要做
- **FP-001**：文件解析核心 — 服务端统一文件解析层，支持 HTML/TXT/MD/PDF 四种格式的文本提取
- **FP-002**：聊天上传入口 — 用户在聊天消息中上传文件，通过 wiki_ingest 工具导入知识库
- **FP-003**：Wiki 面板上传入口 — Wiki 面板增加文件上传按钮/拖拽区域，选择文件后触发解析和摄入
- **FP-004**：文件大小限制 — 10MB 上限，超限时给出明确错误提示；配置项可调整
- **FP-005**：原始文件存档 — 解析后的原始二进制文件存储到知识库 sources/ 目录下，保留原始扩展名

### 本次不做
- 图片格式文件解析（JPG/PNG/GIF 等）
- Office 文档解析（DOCX/XLSX/PPTX）

## 校验触发时机
- 用户选择文件或拖拽文件到上传区域时（文件类型校验 + 文件大小校验）
- 上传文件到服务端时（服务端再次校验文件类型 + 文件大小 + 解析可行性）
- wiki_ingest 工具执行时（解析并提取文本）

## 术语与统一口径
- **文件上传**：用户从本地系统选择文件并发送到服务端的过程
- **文件解析**：服务端将二进制文件转换为纯文本/Markdown 内容的处理过程
- **文件大小**：以字节（Byte）为单位，1MB = 1,048,576 Bytes
- **当前日期**：按服务器时区（UTC+8），按自然日计算（00:00:00~23:59:59）
- **原始文件存档**：将用户上传的原始二进制文件（非提取文本）存储在 sources/ 目录中，文件名保留原始扩展名
- **HTML 结构保留**：保留标题层级（h1-h6）、段落、列表、链接、强调文本，移除 script/style/iframe 等非内容元素

## 数据模型与字段映射

### 文件类型枚举
| 扩展名 | MIME Type | 解析方式 |
|--------|-----------|---------|
| `.html` / `.htm` | `text/html` | htmlToText 增强版（保留标题/列表/链接结构） |
| `.txt` | `text/plain` | 直接 UTF-8 读取 |
| `.md` | `text/markdown` | 直接 UTF-8 读取，保留 Markdown 格式 |
| `.pdf` | `application/pdf` | pdfjs-dist 提取文本 |

### wiki_ingest 输入扩展
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source` | `string` | 否（与 urls/files 至少一个） | 原始文本/Markdown（不变） |
| `urls` | `string[]` | 否（与 source/files 至少一个） | 网页 URL 列表（不变） |
| `files` | `FileInput[]` | 否（与 source/urls 至少一个） | **新增**：上传的文件列表 |
| `title` | `string` | 否 | 资料标题 |
| `category` | `string` | 否 | 分类目录 |

### FileInput 结构（新增）
| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | `string` | 原始文件名（含扩展名） |
| `type` | `string` | MIME Type |
| `size` | `number` | 文件大小（Bytes） |
| `content` | `string` | Base64 编码的文件内容 |
| `path` | `string` | 服务端本地文件路径（可选，替代 content） |

### settings 扩展
| 键 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `wikiMaxFileSize` | `number` | `10485760` (10MB) | 单个文件最大字节数，0 表示不限制 |

### 空值与异常口径
- 文件类型不匹配（非 HTML/TXT/MD/PDF）：拒绝解析，提示 "不支持的文件类型：{type}，支持：HTML/TXT/MD/PDF"
- 文件超过大小限制：拒绝上传，提示 "文件大小 {size} 超过限制 {limit}"
- PDF 无文本层（扫描件）：提取结果为空，提示 "PDF 未包含可提取的文本内容（可能为扫描件）"
- Base64 解码失败：拒绝处理，提示 "文件内容编码异常"
- 文件名含路径穿越字符（`../`、`..\\`）：拒绝处理，提示 "文件名不合法"

## 业务规则
### 规则总表
| 规则 ID | 规则名称 | 说明 |
|---------|----------|------|
| BR-001 | 文件类型白名单 | 仅允许 htm/html/txt/md/pdf 五种扩展名 |
| BR-002 | 文件大小校验 | 单个文件不超过 wikiMaxFileSize 配置值 |
| BR-003 | PDF 文本提取 | 使用 pdfjs-dist 提取文字层文本 |
| BR-004 | HTML 结构保留 | 增强 htmlToText，保留标题/列表/链接结构 |
| BR-005 | 原始文件存档 | 解析后原始二进制文件存入 sources/ 目录 |
| BR-006 | 并发文件处理 | 单次 wiki_ingest 调用可接收多个文件，逐个处理 |

- **BR-001**：文件上传前校验扩展名（不区分大小写），仅 `.htm`、`.html`、`.txt`、`.md`、`.pdf` 通过；其余文件类型拒绝。
- **BR-002**：文件上传前和服务端接收后双重校验大小；超过 `wikiMaxFileSize` 值时拒绝处理；`wikiMaxFileSize = 0` 时不限制大小。
- **BR-003**：使用 `pdfjs-dist` 的 `getTextContent()` 提取所有页面文本，按页码合并；若提取结果为空字符串，按空值口径处理。
- **BR-004**：HTML 文件解析时保留标题层级（h1~h6）、段落、有序/无序列表、超链接文本、强调（strong/em）；移除 script/style/iframe/comment。
- **BR-005**：文件解析完成后，原始二进制以 `{日期}-{slug}.{原始扩展名}` 保存到 `sources/` 目录；存档路径记录在 sourceFile 字段中。
- **BR-006**：`files` 数组中的文件逐个处理，任一文件处理失败不影响其他文件；失败的记录在日志中。

## 错误消息 Contract

### 展示格式
`文件上传 / {文件名} / {错误原因}`

### 排序与去重
- 排序：按文件名在 `files` 数组中的顺序
- 去重：相同文件名 + 相同错误原因只展示一次

### 标准错误文案
| 场景 | 文案 |
|------|------|
| 文件类型不支持 | 文件上传 / {文件名} / 不支持的文件类型，支持：HTML/TXT/MD/PDF |
| 文件超过大小限制 | 文件上传 / {文件名} / 文件大小 {size} 超过限制 {limit} |
| PDF 无文本层（扫描件） | 文件上传 / {文件名} / PDF 未包含可提取的文本内容（可能为扫描件） |
| Base64 解码失败 | 文件上传 / {文件名} / 文件内容编码异常 |
| 文件名不合法 | 文件上传 / {文件名} / 文件名不合法 |

## 验收标准
- [ ] **AC-001**：用户上传 `.txt` 文件 → 服务端正确读取 UTF-8 文本 → 进入 wiki_ingest 编译流程 → 原始文件以 `.txt` 扩展名存档到 sources/
- [ ] **AC-002**：用户上传 `.md` 文件 → 服务端正确读取 Markdown 内容 → AI 编译为 Wiki 页面 → 原始文件以 `.md` 扩展名存档
- [ ] **AC-003**：用户上传 `.html` 文件（含 h1~h3 标题、段落、列表、链接） → 解析后保留标题层级结构 → 原始文件以 `.html` 扩展名存档
- [ ] **AC-004**：用户上传含文本层的 `.pdf` 文件 → pdfjs-dist 提取全部页面文本 → 按页码合并 → 原始文件以 `.pdf` 扩展名存档
- [ ] **AC-005**：用户上传超过 10MB 的文件 → 明确提示超限（含文件大小和限制值） → 文件不被写入 sources/
- [ ] **AC-006**：用户上传不支持的文件类型（如 `.docx`） → 明确提示不支持的类型 → 文件不被写入 sources/
- [ ] **AC-007**：用户在 Wiki 面板中拖拽/选择文件上传 → 文件被解析并进入摄入流程 → 完成后刷新文件树显示新内容
- [ ] **AC-008**：用户在聊天中上传文件并调用 wiki_ingest → 文件被解析并进入摄入流程 → Wiki 面板可见新内容
- [ ] **AC-009**：配置 `wikiMaxFileSize = 20971520` → 支持上传 20MB 以下的文件 → 超过 20MB 拒绝
- [ ] **AC-010**：上传扫描件 PDF（无文本层） → 提示 "未包含可提取的文本内容" → 原始文件仍存档

## 反例
- **反例-001**：用户认为上传 .html 文件应该和 URL 抓取行为完全一致。正确结果：HTML 文件解析保留更多结构（标题/列表/链接），不同于 URL 抓取的粗暴 strip tags。
- **反例-002**：用户认为 PDF 文件上传后可以直接在 Wiki 中查看 PDF 渲染。正确结果：PDF 仅提取文本用于 AI 编译，不提供 PDF 在线阅读功能；原始 PDF 文件以二进制形式存档。
- **反例-003**：用户认为同一个 wiki_ingest 调用中，文件处理失败会中断整个调用。正确结果：BR-006 规定单个文件失败不影响其他文件和已有的 source/urls 处理。

## 非功能性需求
- **NF-001**：PDF 文件超过 100 页时，提取前 100 页文本并提示 "PDF 超过 100 页，仅提取前 100 页"
- **NF-002**：`wikiMaxFileSize` 配置项，支持动态修改无需重启服务

## 风险与依赖
- **依赖项**：`pdfjs-dist` npm 包（Mozilla 官方维护，Apache 许可证）
- **风险项**：pdfjs-dist 包体积较大（约 20MB），可能增加构建时间和 node_modules 体积；大 PDF 文件解析耗时较长
- **应对建议**：pdfjs-dist 按需加载（dynamic import），仅在处理 PDF 时引入；设置 PDF 单次处理超时 30 秒
