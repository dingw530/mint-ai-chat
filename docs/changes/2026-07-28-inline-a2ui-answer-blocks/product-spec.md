# 产品规格：回答内嵌 A2UI 组件

## 文档信息
| 属性 | 值 |
|---|---|
| 状态 | 已完成（已审查） |
| 创建日期 | 2026-07-28 |
| 目标版本 | 待确认 |

## 背景与目标
- 业务背景：Mint 已使用官方 A2UI v0.9 协议展示知识摄入任务，但当前 A2UI 通过会话级专用订阅链路渲染，不能成为普通回答的一部分。
- 当前问题：Wiki 搜索已经返回标题、段落、片段和生命周期信息，但回答无法在文本段之间可靠展示可追溯的来源卡片；刷新后也无法恢复回答中的动态 UI。
- 成功标准：Agent 回答可以在文本段之间插入受控 A2UI 组件；回答刷新后以业务 UI Block 为事实源重建组件；UI Block 丢失不影响文本答案。

## 用户与场景
- 目标用户：使用 Wiki 知识库进行问答的 Mint 用户。
- 典型场景：用户提问后，助手检索 Wiki，在回答中插入来源卡片；用户刷新页面后，正文和来源卡片仍可恢复。

## 用户故事
- **US-001**：作为用户，我希望回答中的 Wiki 来源出现在相关文本段之间，从而能立即判断回答依据。
- **US-002**：作为用户，我希望刷新或重新进入会话后仍能看到已保存的回答组件，从而不丢失上下文。
- **US-003**：作为产品开发者，我希望通过统一 A2UI 入口扩展受控组件，而不让 ReAct 核心循环依赖具体业务组件。

## 范围
### 本次要做
- **FP-001**：在现有 ReactEvent/SSE/IPC 流中增加通用 `a2ui` 事件，承载官方 A2UI v0.9 消息。
- **FP-002**：提供服务端统一 A2UI Composer 入口和受控 Provider/组件注册机制。
- **FP-003**：支持回答 segments 中按顺序插入 A2UI Surface，并复用现有官方 MessageProcessor/Catalog 渲染。
- **FP-004**：以业务 UI Block 作为持久化事实源，回答结束后保存并在刷新时重建 A2UI。
- **FP-005**：实现 Wiki 来源 Block 的生成、引用标记校验和失效标记清理。

### 本次不做
- 不改造现有知识摄入任务的专用 A2UI 订阅链路。
- 不允许 LLM 或数据库动态执行任意组件代码。
- 不实现任意官方 A2UI 组件的开放式持久化。
- 不因 UI Block 持久化失败重试或回滚文本答案。
- 不支持回答文本内部字符级插入，只支持文本段之间插入。

## 业务规则
- **BR-001**：A2UI 事件内层必须通过官方 A2UI v0.9 schema 校验。
- **BR-002**：服务端组件注册表只保存组件契约和启用状态，不保存可执行代码。
- **BR-003**：持久化对象必须是受控、带版本的业务 UI Block，不直接持久化 SurfaceModel 或完整事件历史。
- **BR-004**：文本答案是核心数据；UI Block 保存失败只记录日志，不影响 assistant message 保存和展示。
- **BR-005**：未知 `kind`、版本或未注册组件静默丢弃并记录错误日志。
- **BR-006**：文本中的引用标记只在对应 Block 有效时保留；Block 被丢弃时同步移除标记。
- **BR-007**：回答内嵌 Block 在回答结束时保存最终状态；摄入任务等独立长任务继续使用实时业务表。

## 验收标准
  - [x] **AC-001**：一次包含 Wiki 检索的回答能通过现有 SSE/IPC 链路接收 `a2ui` 事件，并在两个文本段之间渲染来源组件。
  - [x] **AC-002**：`a2ui` 事件内层使用官方 A2UI v0.9 `createSurface`、`updateComponents`、`updateDataModel` 消息，并通过现有解析器和 MessageProcessor。
  - [x] **AC-003**：`reactCoreLoop` 只调用统一 Composer 入口，不直接引用 Wiki 来源组件、具体 A2UI componentName 或 dataPath。
  - [x] **AC-004**：回答结束后文本答案保存成功；UI Block 单独保存失败时，重新加载仍能显示文本答案且不显示孤立引用标记，并产生结构化错误日志。
  - [x] **AC-005**：刷新或重新进入会话后，服务端从版本化业务 UI Block 重建来源组件；未知 Block 被忽略且正文可用。
  - [x] **AC-006**：旧消息没有 UI Block、旧客户端没有组件或 A2UI 数据损坏时，聊天页面不崩溃，并降级为纯文本回答。
  - [x] **AC-007**：服务端和客户端单测、架构边界测试、构建和 Harness 浏览器场景全部通过。

## 非功能性需求
- **NF-001**：A2UI 组件数据必须在服务端校验，客户端对未知组件和错误数据安全降级。
- **NF-002**：HTTP SSE 与 Electron IPC 使用同一 ReactEvent payload，不新增第二套回答协议。
- **NF-003**：UI Block 数据带 `kind` 和 `version`，保留向后兼容读取能力。
- **NF-004**：UI Block 持久化失败日志包含 `messageId`、`kind`、`version` 和错误原因，不记录不必要的完整敏感内容。

## 风险与依赖
- 依赖现有 `ReactEventEmitter`、SSE/IPC 解析、官方 A2UI v0.9 processor 和 Mint Catalog。
- 依赖 Wiki 搜索结果提供可校验的稳定 `chunkId`；当前索引内部已有 chunk 标识，但工具输出需要补齐对外字段。
- 风险：服务端组件契约与客户端 Catalog 版本漂移；通过数据库注册表版本、客户端白名单和未知组件降级缓解。
- 风险：流式答案中断导致 UI Block 不持久化；该结果可接受，因为文本答案优先且 Block 是辅助派生数据。
