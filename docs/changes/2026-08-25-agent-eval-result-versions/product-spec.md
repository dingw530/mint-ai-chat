# Agent Eval 评测结果版本管理

## 背景与目标

`agent-eval` 当前可以把本次报告与一个外部 `--baseline` JSON 文件比较，但默认输出会覆盖 `viewer/report.json`，历史结果缺少稳定标识和可发现的存储入口。目标是让评测维护者可以保存多个不可变结果版本，列出已有版本，并按版本生成可审计的指标差异报告。

## 用户与场景

- 评测维护者运行同一数据集的不同模型、Prompt 或编排版本，并为结果指定稳定版本 ID。
- 模型选型者查看版本清单，确认数据集版本、运行时间和核心指标，再选择两个结果进行对比。
- 回归排查者继续使用现有报告路径作为 baseline，不因新增版本管理破坏已有脚本。

## 范围与非目标

- 做：文件系统版本库、版本 ID 校验、版本保存、版本列表、版本间指标比较和 CLI 文档。
- 做：viewer 中的当前版本/基线版本切换与指标对比入口。
- 做：保留当前 `--baseline <path>` 能力，并让版本比较复用既有 `compareReports` 算法。
- 不做：数据库迁移、生产产品 UI、自动删除/覆盖历史版本、改变确定性门禁或指标定义。
- 不做：把数据集版本和评测结果版本混为同一字段；两者必须分别展示和比较。

## 业务规则

1. 结果版本 ID 只能由小写字母、数字、点、下划线和连字符组成，长度 1–64；路径分隔符和 `..` 不允许。
2. 同一个版本库内版本 ID 不可覆盖；重复保存必须失败并保留原报告。
3. 每个版本保存完整 `EvalReport`，同时在索引中保存数据集名、数据集版本、生成时间和核心摘要，列表不需要读取所有报告内容。
4. 版本比较必须读取两个已保存版本，保留当前 `compareReports` 的同名指标差值和数据集/数据集版本警告。
5. 版本库默认位于 `agent-eval/viewer/versions/`，属于本地生成物；CLI 支持路径覆盖，便于 CI 或临时目录隔离。
6. 确定性 `passed` 仍是评测结果权威字段；版本管理只保存和比较结果，不重新解释通过语义。

## 验收标准

- AC-1：`run --version <id>` 将完整报告保存到版本库，并在重复 ID 时拒绝覆盖。
- AC-2：版本索引可列出 ID、数据集/数据集版本、生成时间、运行次数和核心通过率，并支持按数据集筛选。
- AC-3：`versions:compare --baseline <id> --current <id>` 能生成带基线版本标识和指标差值的 JSON 报告；数据集不一致时给出警告。
- AC-4：既有 `run --baseline <path>` 和默认 `viewer/report.json` 行为保持兼容；不传 `--version` 时自动生成唯一版本 ID 并写入版本库。
- AC-5：版本 ID、缺失版本、重复版本和非法版本库文件均返回可读错误，不产生半成品版本记录。
- AC-6：单元测试覆盖保存、列表、筛选、比较、重复保护、路径安全和 CLI 关键分支；agent-eval 构建通过。
- AC-7：viewer 发现版本索引后显示版本选择器；用户选择当前版本和基线版本并点击比较后，页面展示对应报告和指标差值；无版本索引时仍可查看 `report.json`。

## 风险与依赖

- 风险：本地版本目录可能被清理；完整报告仍是 JSON 文件，调用方可用 `--version-dir` 指向持久化目录。
- 风险：旧报告没有结果版本字段；读取时以文件/CLI 引用作为版本来源，不要求迁移历史报告。
- 依赖：Node 文件系统、现有 `EvalReport` 和 `compareReports`，不引入第三方依赖。
