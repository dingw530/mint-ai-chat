# 文档方法论参考

仅在编写 L1/L2 文档、处理复杂规则或把非结构化需求转成 Spec 时读取。

## 六点框架

按顺序确认：

1. 目标：完成后获得什么能力
2. 范围：做什么、不做什么
3. 约束：安全、性能、兼容、合规边界
4. 决策：使用什么表、接口、组件或状态
5. 任务：如何拆成可验证的工作项
6. 验收：正常、异常、边界和测试要求

未知写“待确认”，不要编造接口、字段、时间或负责人。

## 可判定性检查

涉及状态、字段校验、父子关系、错误拦截、数据映射时，补充：字段路径与类型、枚举语义、触发条件、空值/脏数据处理、时间口径、错误文案 contract 和至少两个反例。

## 非结构化需求转换

| 输入信号 | 转换目标 |
|---|---|
| 功能/页面报错 | 背景、目标、问题定级 |
| 影响用户/数据 | 用户与场景 |
| 操作路径 | 触发条件与验收标准 |
| 不能修改的模块 | 非目标与约束 |
| 修复完成条件 | 验收标准 |
| 接口/权限/数据依赖 | 约束与依赖 |

## 轻量记录

L1 的 `change-note.md` 只保留：

```markdown
# 变更：{主题}

## 目标
{一句话}

## 范围
- 做：{...}
- 不做：{...}

## 验收
- [ ] {可观察条件}

## 验证记录
- {命令/结果}

## 风险与未验证项
- {无则写“无”}
```
